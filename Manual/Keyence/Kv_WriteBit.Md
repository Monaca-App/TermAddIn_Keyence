# コマンドリファレンス：Kv_WriteBit

## 概要

**Kv_WriteBit** は、KEYENCE KV 上位リンクのセット／リセットコマンド（1点時 `ST` / `RS`）または連続書込コマンド（複数点時 `WRS`）を用いて、PLC の **リレー／ビットデバイス（R, MR, LR, B 等）へ ON/OFF 状態を書込** するコマンドです。
書き込み完了後、KV 本体からの正常応答（`OK`）を自動検証します。

---

## 💡 書式・パラメータ仕様

### コマンド構文

```csv
,SEQUENCE, [ステップキー], Kv_WriteBit, "[Device]", "[Values]"
```

### パラメータ（引数）一覧

| 引数位置 | パラメータ名 | 必須/任意 | 型・制約 | 説明 |
| :--- | :--- | :---: | :--- | :--- |
| 第 1 引数 | `Device` | 必須 | 文字列（例: `"MR100"`, `"R500"`, `"LR10"`, `"B0"`） | 書き込みを開始する先頭リレー／ビットデバイス名。 |
| 第 2 引数 | `Values` | 必須 | 文字列（例: `"1"`、`"OFF"`、または `"1, 0, 1"`） | 書き込むビット状態（`1`/`0`, `ON`/`OFF`, `TRUE`/`FALSE` をカンマまたは空白区切りで指定）。 |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における特殊記法および解釈ルールです。
* **動的置換（`$`）**: 引数内で `$PARAMキー$` のように記述すると、実行時に変数プール（PARAM）の値へ動的置換されます。（適用可能な引数: 全引数対応）
* **ジャンプ先指定（`#`）**: 本コマンドはジャンプ制御を行わないため適用されません。（適用可能な引数: 非適用）
* **共通コマンド指定（`@`）**: 本コマンドは外部マクロを呼び出さないため、共通コマンド呼び出し記法は適用されません。（適用可能な引数: 非適用）
* **カンマのエスケープ**: 通信条件文字列（例: `"9600,E,7,1"`）や複数データのカンマ区切り値を単一引数として渡す場合は、必ず `"..."` と二重引用符で囲んで記述します。
* **エイリアス（別名）**: `Kv_Write_Bit`, `Analysis_Kv_WriteBit`

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例

※COMMAND ブロック配下の子要素行（PARAM, SEQUENCE）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください。

```csv
COMMAND, "SAMPLE_KV_WRITEBIT", ""
; 1. 接続開始
,SEQUENCE, 010, Kv_Open, "192.168.0.10", "8501", "TCP"
; 2. MR100 を単一点セット (ST MR100)
,SEQUENCE, 020, Kv_WriteBit, "MR100", "ON"
; 3. MR200〜MR202 に 1, 0, 1 を連続書込 (WRS MR200 3 1 0 1)
,SEQUENCE, 030, Kv_WriteBit, "MR200", "1, 0, 1"
; 4. 切断
,SEQUENCE, 040, Kv_Close
,SEQUENCE, 050, Exit
```

### 実行時の挙動・変数変化

* **実行前の状態**: Term 通信エンジンが初期化され、必要な通信パラメータおよび変数プール（`PARAM`）が準備されている状態。
* **実行後の状態**: ステップ実行により `Kv_WriteBit` の通信制御・プロトコル処理が正常に遂行され、結果または回線状態が更新されます。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や実行時エラーに対し、解析・実行エンジンが実行するセーフティ規約です。

1. **引数範囲・プロトコル書式バリデーション保護**:
   - 必須引数の欠落、デバイス表記・数値範囲の不正、または余剰引数が指定された場合は `_log.LogError` に詳細を記録し、`SetErrorAndHalt` により異常電文の送出を未然に遮断します。
2. **通信タイムアウト・異常応答・排他ドメイン保護**:
   - 相手機器の無応答タイムアウト、NAK／異常終了コード応答、または他通信ドメインとの排他競合が発生した場合は、例外クラッシュを起こさず安全にエラーハンドリングを行います。

## 🧪 ユニットテスト仕様

本コマンドクラス（`Kv_WriteBitCommand.cs`）に実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件

* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより早期リターン）
* **検証結果出力**: `_log.LogTest` によるログ出力。検証失敗時は `_log.LogError`、予期せぬ例外発生時は `_log.LogCritical` で記録し、`finally` ブロックで `KvTransportClient.Shared.IsSimulationMode` を開始前の状態へ復元します。

### テストケース一覧

| No | テストカテゴリ | テスト条件（入力値） | 期待される結果（出力値） | 検証の目的 / 観点 |
| :---: | :--- | :--- | :--- | :--- |
| **1** | 正常系 | `IsSimulationMode = true` 環境下で引数 `"MR100"`, `"ON"` および擬似応答 `"OK\r\n"` を与えて実行 | `!param.HasError` かつ `param.IsCommandGo == true`、`param.SndData == "ST MR100"` となる | 単一点ビット ON 指定時のセットコマンド（`ST`）自動選択および `OK` 応答検証 |
| **2** | 異常系 | 引数不足・過剰（`ValidateParamRange(2, 3)` 違反）、無応答タイムアウト、または KV エラーコード応答（`E0`〜`E6`） | `SetErrorAndHalt(-1, ...)`（または引数検証エラー）によりエラーを記録して安全に停止する | 引数境界検証および書込タイムアウト・KV エラー応答時のフェイルセーフ検証 |
